# Work-package template

Read this when a plan has several streams of work, needs handoffs between owners, or the user asks for a structured plan. A short plan does not need it.

| ID | Work package | Deliverable (what exists afterward) | Done when (observable) | Depends on | Owner | Risk / mitigation |
| --- | --- | --- | --- | --- | --- | --- |
| WP1 | | | | none | only if known or proposed | |

Fill the Owner column only from what the user stated or you are explicitly proposing. Put cross-cutting items below the table:

- **Critical path:** the chain of dependent packages that sets the earliest finish, with the assumption behind each estimate.
- **Parallel tracks:** packages that can run at the same time.
- **Decisions needed:** open choices, who can make them, and which packages wait on each.
- **Checkpoints:** go / no-go points with their criteria, and the rollback path for any irreversible step.
